=============================
Creating Custom Sample Models
=============================

The sample of a simulation (``mg_run``) or a fit (``mg_fit``) is a BornAgain sample, defined in a Python script with a
``get_sample()`` function that returns it. Besides the built-in models, any such script can be used, including the
Python scripts generated by BornAgain itself.

Pass the name of the script (without ``.py``) or its path with ``--model``. It is resolved in two steps:

1. **Local file:** if ``--model`` names an existing ``.py`` file (an absolute path, or a path relative to your current working directory), that file is loaded directly.
2. **Built-in model:** otherwise, ``--model`` is looked up by name among the built-in scripts in ``src/mcstas_gisans/bornagain_samples/`` (see ``--help`` for the current list, e.g. ``silica_100nm_air``, ``silica_100nm_D2O``, ``hexagonal_spheres``, ``lamellas_and_spheres``).

If neither resolves, ``mg_run``/``mg_fit`` exits with an error listing how to see the built-in options.

.. important::

   BornAgain's Python API changes between major versions, so a sample definition written for one BornAgain version
   does not necessarily work with another one (see `BornAgain versions`_ below). Use a script written for the
   BornAgain version you have installed (``python -c "import bornagain; print(bornagain.version_str)"``).

Using a sample exported from BornAgain
--------------------------------------

The Python scripts that BornAgain generates for a sample (exported from the BornAgain GUI, or the example scripts of
the BornAgain documentation) can be used without changes: they define the sample in a ``get_sample()`` function, and
only that function is used. The beam, detector and simulation they define (``get_simulation()``, the
``if __name__ == '__main__':`` block) are ignored, since ``mcstas_gisans`` provides the beam from the McStas
simulation and its own detector. For example, with the BornAgain example script *CylindersAndPrisms.py* and the D22
setup of :doc:`quickstart`:

.. code-block:: bash

    mg_run data/paper/mcstas_output/d22_1e9/test_events.mcpl.gz \
      --instrument d22 --wavelength_selected 6.0 --intensity_factor 0.2107 \
      --sample_size_y 0.06 --sample_size_x 0.08 --allow_sample_miss \
      --alpha 0.24 --sample_orientation 2 --instrument_detector_centre_offset 0.290838 -0.016061 \
      --specular specular_simulation \
      --model ./CylindersAndPrisms.py

The script must be written for the installed BornAgain version (scripts exported by BornAgain 23 run with
BornAgain 22 and 23, but not with 24). An exported ``get_sample()`` has no arguments, so all sample values are fixed in
the script; to change them from the command line or to fit them, turn them into keyword arguments of ``get_sample``,
as in the template below.

Basic Template
--------------

A template for a custom sample model: silica spheres on a silicon substrate in air, a simplified version of the
built-in ``silica_100nm_air`` model of the D22 example (:doc:`quickstart`). It is written for **BornAgain 22 and 23**
(tested with 22.2 and 23.0; it does not run with BornAgain 24, see `BornAgain versions`_ for the differences). Save it
as *silica_spheres_on_silicon.py*:

.. code-block:: python

    import bornagain as ba
    from bornagain import deg, nm, nm2

    # BornAgain versions this model is tested with (first, last major version)
    BORNAGAIN_VERSIONS = (22, 23)

    def get_sample(radius=51.0, lattice_parameter=114.0, lattice_size=5, position_variance=20.0):
        """
        Silica spheres on a silicon substrate, in air, in finite hexagonal 2D crystallites
        (BornAgain 22 and 23).

        The keyword arguments are the sample parameters: their names are the names used on
        the command line (--sample_arguments, --fit, --scan); the defaults are used for the
        parameters that are not given there.

        radius : radius of the spheres [nm]
        lattice_parameter : nearest-neighbour distance of the spheres [nm]
        lattice_size : number of spheres along each lattice axis of a crystallite
        position_variance : variance of the sphere positions around the lattice sites [nm^2]
        """
        # 1. Materials (scattering length densities in 1/A^2)
        material_air = ba.MaterialBySLD("Air", 0.0, 0.0)
        material_silica = ba.MaterialBySLD("SiO2", 3.47e-6, 0.0)
        material_silicon = ba.MaterialBySLD("Silicon", 2.07e-6, 0.0)

        # 2. The particle: a silica sphere
        particle = ba.Particle(material_silica, ba.Sphere(radius*nm))

        # 3. The interference function: finite hexagonal crystallites of lattice_size x lattice_size
        #    spheres, averaged over all in-plane orientations
        lattice = ba.BasicLattice2D(lattice_parameter*nm, lattice_parameter*nm, 120*deg, 0*deg)
        n = int(max(1, round(lattice_size)))  # BornAgain needs an integer (a fitted value is a float)
        interference = ba.InterferenceFinite2DLattice(lattice, n, n)
        interference.setIntegrationOverXi(True)
        interference.setPositionVariance(position_variance*nm2)

        # 4. The particle layout
        layout = ba.ParticleLayout()
        layout.addParticle(particle)
        layout.setInterference(interference)

        # 5. The layers: the spheres sit on the substrate (bottom of the top layer)
        air_layer = ba.Layer(material_air)
        air_layer.addLayout(layout)
        substrate_layer = ba.Layer(material_silicon)

        # 6. The sample
        sample = ba.Sample()
        sample.addLayer(air_layer)
        sample.addLayer(substrate_layer)

        return sample

With its default parameters it describes the D22 measurement of the example about as well as the built-in model.

Sample parameters on the command line
-------------------------------------

Any keyword argument of ``get_sample`` can be set from the command line, without changing the script or
``mcstas_gisans``: the command line tools do not need to know the parameters of a model. They are given with
``--sample_arguments`` as one string of ``name=value`` pairs separated by semicolons (quote the string, the shell
would otherwise split it at the semicolons):

.. code-block:: bash

    mg_run data/paper/mcstas_output/d22_1e9/test_events.mcpl.gz \
      --instrument d22 --wavelength_selected 6.0 --intensity_factor 0.2107 \
      --sample_size_y 0.06 --sample_size_x 0.08 --allow_sample_miss \
      --alpha 0.24 --sample_orientation 2 --instrument_detector_centre_offset 0.290838 -0.016061 \
      --specular specular_simulation \
      --model ./silica_spheres_on_silicon.py \
      --sample_arguments "radius=48;lattice_parameter=110;lattice_size=8"

This calls ``get_sample(radius=48, lattice_parameter=110, lattice_size=8)``, with the default
``position_variance=20.0``. The rules:

- the names are the keyword argument names of ``get_sample``; the parameters that are not given keep their default
  values;
- the values are converted to ``int`` or ``float`` if they are numbers, to ``True``/``False`` for ``true``/``false``,
  to ``None`` for ``none``, and are passed as strings otherwise (e.g. ``"shape=sphere"``);
- a name that ``get_sample`` does not accept is ignored with a warning listing the accepted names (so a typo does not
  go unnoticed). If ``get_sample`` takes ``**kwargs``, every name is passed to it unchecked.

``mg_fit`` uses the same mechanism: the fitted parameters (``--fit``) and the scanned ones (``--scan``) are passed to
``get_sample`` as keyword arguments by name, and ``--sample_arguments`` sets the fixed (not fitted) parameters. The
same holds for the built-in models, e.g. ``--sample_arguments "radius=51;latticeParameter=114"`` for
``silica_100nm_air`` (``--help`` lists the built-in models; their parameters are the keyword arguments of their
``get_sample``).

BornAgain versions
------------------

BornAgain's Python API changes between major versions: BornAgain 22 replaced ``ba.MultiLayer``
with ``ba.Sample`` and moved the interface roughness into the layers, and BornAgain 24 changed
the materials (``ba.MaterialBySLD`` became ``ba.SLDMaterial`` with a colour argument) and replaced
the particle layouts (``ba.ParticleLayout`` with an interference function) by structures that
contain the particles (``ba.FiniteCrystal2D``, ``ba.Crystal2D``, ``ba.Paracrystal2D``, a
``ba.Mixture`` for several particle types) placed with ``layer.deposit2D``/``layer.suspend2D``.
A model is therefore written for one API.

The built-in models are kept in version folders of ``bornagain_samples/``, named after the first
BornAgain major version of the API they are written for: ``ba21/`` (BornAgain 21), ``ba22/``
(BornAgain 22 and 23) and ``ba24/`` (BornAgain 24). A model can have an implementation in several
folders under the same name, and a file can declare the major versions it is tested with:

.. code-block:: python

    # BornAgain versions this implementation is tested with (first, last major version)
    BORNAGAIN_VERSIONS = (22, 23)

``--model <name>`` uses the implementation whose range contains the installed BornAgain version;
an implementation without ``BORNAGAIN_VERSIONS`` is treated as compatible with any version. If
neither exists, the run stops with an error that lists the available implementations: an
implementation is never used silently with a BornAgain version outside its declared range (a newer
BornAgain can change the results without breaking the API). ``--allow_untested_bornagain_version``
uses the implementation for the newest older version anyway, with a warning. Declaring the versions
is suggested, not required. The folder layout is explained in ``bornagain_samples/README.md``. ``--help`` lists the
built-in models with their tested versions. Model files given as a path, and files placed directly
in ``bornagain_samples/``, are not version-checked.

To support a new BornAgain version (say 25): run the tests with it.
``tests/test_sample_versions.py`` simulates every model available for the version against its
stored reference results (``tests/data/builtin_model_references.json``); for a model whose
implementation still works and gives the reference results, extend its range, e.g.
``BORNAGAIN_VERSIONS = (24, 25)``. For a model that needs the new API, add an implementation with the
same name in a new folder ``ba25/`` with
``BORNAGAIN_VERSIONS = (25, 25)``, write its reference results with
``python tests/make_builtin_model_references.py`` (with BornAgain 25 installed), and check that they
agree with those of the older implementation. Models that are not updated are simply not available
with the new version.

Differences to keep in mind when writing a BornAgain 24 implementation of a 22/23 model:

- the position variance: ``setPositionVariance(v)`` with a variance v [nm\ :sup:`2`] became
  ``setLateralPositionVariance(s)`` with the root-mean-square displacement s = sqrt(v) [nm];
- the vertical position: ``layer.suspend2D`` (particles below the top interface of a layer, as
  ``addLayout`` in a lower layer before) positions a particle by its *top*, ``layer.deposit2D``
  (particles on the bottom of the top layer) by its bottom; BornAgain 22/23 positioned it by its
  origin, the bottom of the form factor;
- the particle surface density is one particle per unit cell of the lattice in all versions
  (BornAgain 22/23 ignore ``setTotalParticleSurfaceDensity`` with a 2D lattice);
- BornAgain 24 uses average materials by default (21-23 did not); ``mcstas_gisans`` always sets the
  option explicitly, by default on (``--use_avg_materials``, off with ``--no_use_avg_materials``); with average materials the BornAgain 24 implementations of the
  built-in models give the same results as the 22/23 ones, without them particles inside a lower
  layer give a much lower intensity with BornAgain 24.1.

Using the Template with ``mg_fit``
----------------------------------

The template can be fitted to the D22 measurement included in the repository
(``data/paper/d22_measurement/073174.nxs``, 3 hours), here the sphere radius and the lattice parameter, with the
region below :math:`Q_z = 0.14\,\mathrm{nm}^{-1}` (transmitted beam, specular reflection and Yoneda region) masked:

.. code-block:: bash

    mg_fit data/paper/mcstas_output/d22_1e9/test_events.mcpl.gz \
      --nxs data/paper/d22_measurement/073174.nxs --experiment_time 10800 --fit_background \
      --instrument d22 --wavelength_selected 6.0 --intensity_factor 0.2107 \
      --sample_size_y 0.06 --sample_size_x 0.08 --allow_sample_miss \
      --alpha 0.24 --sample_orientation 2 --instrument_detector_centre_offset 0.290838 -0.016061 \
      --specular specular_simulation \
      --model ./silica_spheres_on_silicon.py --sample_arguments "lattice_size=5" \
      --mask_qz_min_cut 0.14 \
      --fit radius 51 45 57 --fit lattice_parameter 114 100 130 \
      --max_evals 20 --output_dir fit_template

The ``--fit`` flag can be repeated once per parameter, and accepts either ``name x0`` (fixed
initial guess, unbounded), ``name min max`` (bounds, with the initial guess set to their
midpoint), or ``name x0 min max`` (explicit initial guess and bounds). Here
``--fit radius 51 45 57`` starts the optimizer at a radius of 51 nm and searches between 45 nm and 57 nm. The fitted
values are passed to ``get_sample`` as keyword arguments by name; as for ``--sample_arguments``, a name your function
does not declare (and does not catch via ``**kwargs``) is ignored, with a warning printed to the console. The same fit
of the built-in model is explained in section 9 of the :doc:`fitting_guide`.

Under the hood, ``mg_fit`` selects an optimizer with ``--optimizer``: ``nelder-mead`` (default),
``powell``, or ``differential-evolution`` (which requires finite bounds on every fitted
parameter). Each iteration re-runs the full McStas-particles-through-BornAgain simulation and
scores it against the experimental NeXus data over the *unmasked* detector region only, using a
loss function selected with ``--loss_function`` (``poisson_deviance`` by default, or
``reduced_chi2``/``log_residual``; see :ref:`loss-functions` for which to choose) — see
:doc:`main_workflow` for how ``--mask_*`` options control which region counts towards the loss,
and for the simpler grid-search alternative, ``--scan``.
